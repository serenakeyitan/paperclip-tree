Paperclip adapters can now execute agent runs against a remote SSH environment in addition to the local host. The provider-neutral contract is the `AdapterExecutionTarget` (in `packages/adapter-utils/src/execution-target.ts`), which is either `{ kind: "local" }` or `{ kind: "remote", transport: "ssh", spec, remoteCwd, ... }`. Adapters consume this target through helpers such as `runAdapterExecutionTargetProcess`, `prepareAdapterExecutionTargetRuntime`, and `ensureAdapterExecutionTargetCommandResolvable` instead of calling `runChildProcess` directly, so every adapter (claude-local, codex-local, cursor-local, gemini-local, opencode-local, pi-local) gets remote execution behavior for free.

The SSH transport itself lives in `packages/adapter-utils/src/ssh.ts`. It owns connection config (`SshConnectionConfig`/`SshRemoteExecutionSpec`), the `runSshCommand`/`shellQuote`/`buildSshSpawnTarget` primitives, and workspace sync helpers (`prepareWorkspaceForSshExecution`, `restoreWorkspaceFromSshExecution`, `syncDirectoryToSsh`). A managed-runtime layer (`remote-managed-runtime.ts`) stages workspace + adapter assets onto the remote host and produces a session identity used to detect when a run can reuse an existing remote session.

Agents now carry a default environment. Migrations `0067_agent_default_environment.sql` and `0068_environment_local_driver_unique.sql` add `agents.default_environment_id` and enforce uniqueness of the local-driver environment per company; `CreateConfigValues.defaultEnvironmentId` and the agent/environment validators in `packages/shared` expose this on the API surface. Runs without an explicit environment fall back to the agent default, and `kind: "local"` continues to mean "execute on the Paperclip host".

For local development and CI, the CLI ships an `env-lab` command (`cli/src/commands/env-lab.ts`, registered in `cli/src/index.ts`, documented in `doc/CLI.md`) that brings up an OpenSSH-based fixture under `instances/<id>/env-lab/ssh-fixture/`. `env-lab up|down|status|doctor` start/stop/inspect the fixture; `getSshEnvLabSupport` reports whether the host can run it. Adapter integration tests (`execute.remote.test.ts` in each adapter) drive adapters end-to-end against this fixture, and `sanitizeInheritedPaperclipEnv` plus the new `PAPERCLIP_RUNTIME_API_URL` variable keep host-side Paperclip env vars from leaking into the remote shell while still letting the agent reach the control plane.
